# 01 Motion Philosophy

## 1.1 动态世界观

《昨日重现》的UI不是悬浮在游戏之上的数字界面，而是一套正在被翻阅、辨认和修复的家庭档案。

玩家触摸按钮时，不是按下现代控件，而是触碰一张保存多年的纸签。玩家打开页面时，不是进入新的App界面，而是翻开一本相册、抽出一份档案或揭开一张被覆盖的照片。

动态语言必须始终服务于三个行为：

1. 触碰旧物。
2. 唤醒记忆。
3. 恢复过去。

## 1.2 Memory Motion Language

| 运动语义 | 玩家感受 | 动态表现核心 | 使用场景 |
|---|---|---|---|
| Discover 发现 | “这里有一段线索。” | 遮挡减弱、局部清晰、纸边或照片边缘被注意到 | Partial节点、可查看照片、未知线索 |
| Awaken 唤醒 | “这段记忆正在回应我。” | 暖光从触点或物件内部出现，墨迹与影像逐渐显露 | 开始回忆、Hold显影、关键节点 |
| Restore 恢复 | “破损的信息重新完整。” | 碎片归位、边缘闭合、色彩与连接恢复 | 拼图、破损照片、Memory Node完成 |
| Confirm 确认 | “这段记忆已经被保存。” | 动作收束、归档标记稳定、动态停止 | Completed、Recovered、章节归档 |
| Recede 褪去 | “记忆暂时离开视线。” | 光线回落、纸张合拢、内容退回档案层 | 关闭面板、返回、记忆短暂消退 |

## 1.3 四项动态品质

### 旧物质感

- 纸张运动需要有轻微重量、阻力和层次。
- 照片运动比纸签更稳、更重。
- 胶带、回形针和图钉只产生从属位移，不独立表演。
- 动态不能让旧物表现得像无重量的数字卡片。

### 记忆苏醒

- 重要反馈从局部显影开始，而不是全屏突然变亮。
- 恢复过程由模糊、缺失或低饱和走向清晰。
- 暖金高亮表示记忆被唤醒，不表示普通商业奖励。

### 时间流动

- 页面展开应有“被翻开”的起因和方向。
- 旧内容退出时应留下短暂层次，而不是瞬间消失。
- 关键记忆允许比普通操作更慢地完成收束。

### 温暖但克制

- 大部分反馈只作用于当前对象。
- 全屏光效仅用于关键剧情阈值。
- 不使用夸张弹跳、强烈缩放、连续闪烁或高频粒子。

## 1.4 禁止的动态语言

| 禁止表现 | 原因 |
|---|---|
| 科技HUD扫描线、雷达扩散、数字网格 | 破坏家庭档案世界观 |
| 现代App式卡片上浮与标准淡入淡出 | 缺乏旧物重量和叙事来源 |
| 快速连续弹跳、果冻回弹 | 情绪过于轻快，削弱遗憾感 |
| 霓虹描边、蓝色能量流 | 与暖色旧物系统冲突 |
| 无来源的粒子爆炸 | 将记忆恢复变成商业奖励 |
| 所有元素同时运动 | 信息层级失控，降低可读性 |
| 持续循环发光 | 造成催促和视觉疲劳 |

# 02 Global Motion Rules

## 2.1 物件运动方向

| 对象 | 进入方向 | 退出方向 | 核心运动语义 |
|---|---|---|---|
| 主纸张Panel | 从档案、相册或桌面层中展开 | 合拢、退回或滑回原档案层 | 打开与收起一份记录 |
| 侧边档案抽屉 | 从对应页面边缘抽出 | 沿原方向推回 | 抽取与归还档案 |
| 页面Tab | 向内容区域伸出 | 收回索引边缘 | 当前分类被抽出查看 |
| 普通照片 | 从原位抬起并聚焦 | 回到原叠放位置 | 拿起与放回照片 |
| 破损照片 | 碎片向合法位置聚合 | 失败时返回上一个有效位置 | 整理与修复 |
| Memory Node | 从隐藏、模糊、局部显影走向稳定 | 非销毁状态不做消失表演 | 记忆从不可辨认到可确认 |
| Button | 向纸面内部压入，再释放 | 不单独退出；随所在Panel离开 | 手指压住纸签 |
| 印章与归档勾 | 从未完成状态落定 | Completed状态通常不退出 | 记录被正式确认 |

## 2.2 材质运动规律

### 纸张

- 展开时保持一个明确的固定边、装订边或来源边。
- 纸张主体先移动，阴影随后适应新的层级。
- 纸边可以有轻微不一致，但文字基线与可读区域必须稳定。
- 关闭时沿进入路径反向收回，不随意改变来源方向。

### 照片

- 聚焦时先脱离叠放阴影，再建立清晰度。
- 放大只服务查看，不把照片变成现代全屏卡片。
- 完整照片的运动比破损碎片更稳，避免持续漂浮。

### 胶带、回形针与图钉

- 跟随所属纸张或照片运动。
- 可产生极轻微的从属滞后，以表现固定关系。
- 不允许独立旋转、弹跳或发光。

### 墨迹与印章

- 墨迹显露可以由浅到深、由断续到完整。
- 印章只在完成确认时出现或落定。
- 普通按钮点击不得反复盖章。

## 2.3 运动轴

| 运动轴 | 使用原则 |
|---|---|
| Z轴层级 | 用于按钮压入、照片抬起、Panel前后层次 |
| 水平轴 | 用于侧边抽屉、分类档案、相邻页面关系 |
| 垂直轴 | 用于列表浏览、纸张从桌面层中展开 |
| 中心聚合 | 仅用于碎片修复、记忆显影和关键恢复 |
| 局部扩散 | 仅用于暖光从触点或照片内部唤醒 |

## 2.4 动画层级

| 层级 | 名称 | 适用内容 | 运动权限 |
|---|---|---|---|
| Level 1 | Narrative Motion | 开始回忆、关键记忆恢复、章节完成、进入过去 | 可带动主Panel、背景光和关键照片；同屏唯一主运动 |
| Level 2 | Page Motion | 打开档案、展开报告、切换分类、打开详情抽屉 | 作用于页面结构；不得抢夺Level 1焦点 |
| Level 3 | Component Motion | Button、Tab、Photo Card、Node的状态反馈 | 只作用于当前组件及其直接附属元素 |
| Level 4 | Ambient Motion | 纸尘、光线、极轻微环境呼吸 | 不承载信息；必须可停止或弱化 |

## 2.5 同屏运动预算

- 同一时刻只允许一个Level 1运动。
- Level 1进行时，Level 3只保留必要的触控确认。
- 同一区域最多一个主运动和一个从属运动。
- 列表滚动期间，列表项不自动播放独立循环动效。
- Ambient Motion不能与记忆恢复竞争亮度、对比或方向。

## 2.6 动态焦点规则

1. 先确定本次动作的唯一主对象。
2. 主对象获得最完整的材质、阴影和清晰度变化。
3. 关联对象只产生弱化的从属变化。
4. 无关对象保持稳定或轻微压暗。
5. 动作完成后，页面恢复稳定可读状态。

# 03 Button Motion Specification

## 3.1 普通按钮Motion Flow

适用于Secondary Button、Bottom Button、普通Icon Button及不承担叙事阈值的Primary Button。

### Idle

| 层 | 动态状态 |
|---|---|
| 纸张 | 保持Visual Bible规定的旧纸状态，不循环呼吸 |
| 阴影 | 稳定，明确按钮与底纸层级 |
| 边缘 | 保持磨损与纸纤维，不主动发光 |
| 图标 | 保持旧印刷线稿状态 |
| 文字 | 稳定可读，不闪烁、不漂移 |

### Touch Down

| 层 | 动态变化 |
|---|---|
| 纸张 | 向内部压入，表现手指作用于纸面 |
| 阴影 | 收紧并靠近纸张，减少悬浮感 |
| 边缘 | 接触区域略微加深；不出现现代描边框 |
| 图标 | 与纸面同步压入，可轻微增强墨色 |
| 文字 | 保持位置稳定，避免压入时变得模糊 |
| 触控归属 | 只反馈当前Hitbox对应按钮 |

### Touch Release Valid

| 层 | 动态变化 |
|---|---|
| 纸张 | 从压入状态释放并回到稳定层级 |
| 阴影 | 恢复至目标状态的阴影 |
| 边缘 | 出现一次克制的确认亮边或纸纤维显露 |
| 图标 | 完成一次清晰确认，不独立弹跳 |
| 状态 | 执行Action Trigger并进入Selected、Completed或Transition Lock |

### Touch Release Invalid

- 撤销Pressed表现。
- 沿原路径回到Idle或原Selected状态。
- 不播放确认反馈。
- 不产生页面转场或数据写入。

### Disabled

- 不响应Touch Down运动。
- 不使用轻微弹动暗示可点击。
- 若交互规范要求说明，可由独立提示承担，不让Disabled按钮本身“挣扎”。

### Selected

- 纸签保持伸出、稳定亮边或归档标记。
- 再次Touch Down从Selected基线压入。
- Release无效时回Selected，而不是回Idle。

## 3.2 普通按钮动作纪律

| 规则 | 要求 |
|---|---|
| 回弹 | 表现纸张释放，不做弹簧式多次振荡 |
| 缩放 | 只用于建立压入层级，不能像现代App按钮突然放大 |
| 高亮 | 普通按钮只使用局部确认，不产生大范围暖光 |
| 图标 | 始终跟随按钮本体，不独立飞入或旋转 |
| 连续点击 | Action Lock期间不重复播放完整Release确认 |

## 3.3 记忆唤醒按钮

记忆唤醒按钮用于“开始回忆”、关键章节继续、确认重大恢复等叙事阈值。它与普通按钮的区别不是更亮、更大或更吵，而是触摸过程具备完整的“旧物回应玩家”语义。

### 触碰前：Dormant Memory

| 层 | 状态 |
|---|---|
| 纸张 | 普通旧纸状态，保存年代痕迹 |
| 阴影 | 稳定，略重于普通按钮 |
| 边缘 | 暖金只保留极弱的潜在线索，不循环闪烁 |
| 图像线索 | 可见但褪色，像尚未完全想起的片段 |
| 图标与文字 | 清晰、克制，保持最高级入口的可读性 |

### 手指按下：Memory Awakening

| 阶段 | 动态语义 |
|---|---|
| 接触确认 | 纸张向内压入，阴影收紧 |
| 记忆响应 | 暖光从接触对象内部或记忆图像边缘出现 |
| 信息显影 | 褪色图像、纸纤维或墨迹出现局部清晰 |
| 焦点收束 | 周围次级入口保持稳定或轻微退后 |

Touch Down不等于确认。手指移出有效范围时，唤醒过程必须可逆地回到Dormant Memory。

### 有效释放：Memory Confirmed

| 阶段 | 动态语义 |
|---|---|
| 释放 | 纸张从压入状态恢复，但不回到完全Dormant |
| 确认 | 暖光完成一次从局部到按钮整体的收束 |
| 归一 | 图标、文字与记忆图像达到短暂统一清晰 |
| 交接 | 按钮进入Transition Lock，将动态焦点交给页面转场 |

### 进入下一场景：Enter the Past

1. 按钮本体的确认运动完成闭环。
2. 按钮中被唤醒的图像、光线或纸面方向成为转场的视觉来源。
3. 主菜单其他元素退回档案层，不进行各自独立退场表演。
4. 游戏场景从该记忆来源中接管画面。
5. 场景接管完成后，菜单不再保留可交互反馈。

## 3.4 “开始回忆”完整Motion Flow

| 交互状态 | 动态状态 | 声音占位 | 触感占位 | 打断结果 |
|---|---|---|---|---|
| Idle | Dormant Memory；旧纸与褪色线索稳定 | 环境底噪 | 无 | 可进入Touch Down |
| Touch Down | 纸张压入；局部暖光与显影开始 | 纸面接触音 | 轻触确认 | 移出则逆向回Idle |
| Touch Hold | 显影保持，不继续无限增强 | 低强度记忆共鸣 | 稳定弱反馈 | Release无效则回Idle |
| Touch Release Valid | 释放、显影收束、入口确认 | 记忆确认音 | 明确单次确认 | 不可重复触发 |
| Transition Lock | 按钮将动态焦点交给场景入口 | 主题声源接管 | 无额外连续震动 | 目标失败则回可操作状态 |
| Scene Handoff | 由纸面/照片记忆来源进入游戏画面 | 场景声音接管 | 按场景规范 | 菜单交互结束 |

# 04 Panel Motion

## 4.1 Panel类型与运动来源

| Panel | 物理隐喻 | 进入方式 | 退出方式 |
|---|---|---|---|
| 记忆档案主Panel | 打开的相册或档案盒 | 从主菜单的档案入口展开 | 合拢并退回档案入口 |
| 右侧详情抽屉 | 从档案盒中抽出的个人记录 | 从右侧索引边抽出 | 沿原方向推回 |
| 章节恢复报告 | 新归档的一页恢复记录 | 从游戏结果中铺开、落定 | 由继续按钮引向下一记忆 |
| 设置页面 | 被夹在档案中的功能页 | 从设置Icon对应位置展开 | 收回原功能页层级 |
| 确认Panel | 临时覆盖在当前档案上的纸张 | 从当前操作对象附近展开 | 确认后归档或取消后收回 |

## 4.2 Panel进入

1. 明确来源：书页、档案边缘、按钮、照片或场景物件。
2. 背景先降低交互优先级，不突然全黑。
3. Panel主体展开或抽出。
4. 阴影建立层级。
5. 标题与主要信息随Panel稳定后变得完全清晰。
6. Panel进入Stable状态后开放触控。

## 4.3 Panel退出

1. 当前触控与滚动结束。
2. Panel进入不可重复触发的关闭状态。
3. 次要内容先退回纸面层级。
4. Panel沿来源方向合拢或收回。
5. 背景恢复交互优先级。
6. 返回页恢复Interaction Bible定义的浏览态。

## 4.4 展开与关闭规则

| 规则 | 要求 |
|---|---|
| 运动方向一致 | 同一Panel进入与退出沿相反路径 |
| 触控时机 | Panel未稳定前不接受内部操作 |
| 文字稳定 | 正文不单独飞入；随纸张层级出现 |
| 背景处理 | 使用档案层级退后，不使用现代模态黑幕 |
| 打断 | 用户返回可请求关闭；已进入关键归档提交时按Interaction Bible完成提交后再退出 |

## 4.5 记忆档案

- 主Panel像打开相册或档案盒。
- 左分类栏随主Panel一起建立，不逐个Tab弹入。
- 中央关系图在纸面稳定后显露节点。
- 右详情抽屉只在Node Selected后抽出。
- 切换分类不关闭整个档案，只替换当前索引页内容。

## 4.6 章节报告

- 报告像新完成的一页记录铺在档案上。
- 结果、恢复列表、未知记忆按视觉阅读顺序建立清晰度。
- 不要求每个条目逐个飞入。
- 归档勾与清晰度结果属于完成信息，应在报告稳定时已存在。

## 4.7 设置页面

- 设置页动效等级为Level 2。
- 不使用记忆恢复级暖光。
- 开关与选项仍遵循旧纸、题签和压入反馈。
- 返回时沿设置入口方向收回。

# 05 Photo Motion

## 5.1 普通照片：查看与聚焦

| 阶段 | 动态表现 |
|---|---|
| Idle | 保持叠放、相纸阴影与年代颗粒 |
| Touch Down | 照片轻微压向底纸，确认接触 |
| Selected | 从叠放层抬起，阴影与清晰度增强 |
| Focus | 移向Visual Bible规定的查看位置并适度放大 |
| Close | 沿原路径回到原叠放位置与角度 |

规则：

- 聚焦不改变照片恢复等级。
- 放大时照片中心内容保持稳定，不进行透视翻转。
- 胶带与回形针若属于照片本体，跟随移动。
- 背景照片保持原位或轻微退后，不四散飞开。

## 5.2 破损照片：恢复

### 碎片聚合

- 碎片只响应合法Drag。
- Drag时碎片跟随触点，保留纸张重量感。
- 接近合法位置时，目标边缘出现局部吻合反馈。
- Release Valid后碎片落入正确层级。
- Release Invalid后返回上一个有效位置，不弹飞。

### 边缘修复

- 正确碎片之间的裂缝由明显转为细微。
- 修复从已连接的边缘向内部收束。
- 不使用激光扫描或能量缝合。
- 胶带修补只在叙事和视觉规范允许时出现。

### 颜色恢复

- 色彩从已恢复内容内部扩散。
- 先恢复关键人物、物件或记忆中心，再恢复环境。
- 色彩不达到现代数码照片的鲜艳度。
- 最后保留Visual Bible定义的年代颗粒与轻微泛黄。

## 5.3 完整照片：稳定记忆

| 动态属性 | 规范 |
|---|---|
| 呼吸 | 不持续缩放或发光 |
| 清晰度 | 保持稳定，不反复模糊 |
| 颜色 | 保持Recovered状态，不循环增艳 |
| 归档标记 | 稳定存在，不重复盖章 |
| 再次查看 | 可执行普通照片聚焦，但不重复恢复演出 |

## 5.4 Photo Recovery Motion Flow

| 状态 | 主运动 | 可打断性 | 数据关系 |
|---|---|---|---|
| Before Memory | 破损、褪色、缺失保持静止 | 可离开 | 不写入Recovered |
| Memory Reconstruction | Drag、组合、局部吻合反馈 | 可按Interaction Bible取消或放弃 | 临时位置与阶段性结果 |
| Final Condition Met | 最后一块归位，修复运动开始收束 | 不接受新的碎片拖动 | 等待完成确认 |
| Recovered | 边缘、色彩、归档标记稳定 | 不回退到破损状态 | 写入Recovered / Completed |

# 06 Memory Node Motion

## 6.1 Unknown

### 动态语义

沉默、隐藏、尚未形成可以辨认的记忆。

| 属性 | 规范 |
|---|---|
| 运动 | 基本静止，不通过晃动吸引玩家 |
| 清晰度 | 保持模糊、缺损或遮挡 |
| 连接线 | 不出现，或保持极弱、断开的痕迹 |
| 光线 | 不主动发光 |
| Touch | 若不可用则Disabled；若可调查，只提供发现级反馈 |

## 6.2 Partial

### 动态语义

玩家发现了一部分线索，记忆正在建立连接。

| 阶段 | 动态表现 |
|---|---|
| 发现 | 节点从背景层中变得可辨认 |
| 局部显影 | 关键区域清晰，非关键区域仍保留缺失 |
| 建立连接 | 连接从已有节点向Partial节点延伸并停在未完成状态 |
| Selected | 节点抬升，相关连接增强，右侧详情抽屉展开 |
| 退出Selected | 回到Partial稳定状态，不退回Unknown |

## 6.3 Recovered

### 动态语义

信息被完整确认，并作为稳定档案存在。

| 阶段 | 动态表现 |
|---|---|
| 完成触发 | Partial中的显影与连接完成收束 |
| 节点恢复 | 影像达到Recovered清晰度与色彩 |
| 连接稳定 | 断续关系线转为完整稳定线 |
| 归档确认 | 归档勾或小印章落定 |
| 稳定状态 | 停止主运动，只保留静态完成标记 |

## 6.4 节点选择

- Node Selected是交互状态，不等同恢复等级。
- Unknown、Partial、Recovered均可拥有自己的Selected表现。
- Selected只强化当前节点与直接关联线。
- 切换节点时，旧节点先回到自己的业务状态，新节点再成为动态焦点。
- 右侧抽屉更新时不要求整个关系图重排。

## 6.5 连接线

| 场景 | 动态规则 |
|---|---|
| Unknown关系 | 不绘制完整连接运动 |
| Partial建立 | 从已知端向未知端延伸，保留未完成终点 |
| Recovered完成 | 连接闭合并稳定，不循环流动 |
| Selected强调 | 相关线局部增强，不产生科技能量流 |
| 关系图平移 | 线与节点作为同一图层同步移动 |

# 07 Page Transition Motion

## 7.1 转场原则

页面切换必须回答：

1. 玩家从哪件旧物离开？
2. 玩家打开了哪份记忆？
3. 新页面与原页面在档案空间中的关系是什么？

禁止把普通Fade作为完整转场方案。Fade可以作为光线、景深或记忆模糊的从属变化，但必须依附于翻页、展开、抽屉、照片聚焦或进入场景等主动作。

## 7.2 页面关系

| 来源 | 目标 | 转场隐喻 | 主运动 |
|---|---|---|---|
| 启动 | 主菜单 | 旧皮箱或相册被看见 | 环境光建立，主相册进入可读层 |
| 主菜单 | 游戏场景 | 进入一段被唤醒的过去 | 由“开始回忆”按钮中的记忆线索接管画面 |
| 主菜单 | 记忆档案 | 翻开相册或抽出档案盒 | 主菜单退为桌面层，档案主Panel展开 |
| 游戏场景 | 章节报告 | 将刚恢复的内容写入档案 | 场景结果凝聚为报告纸页 |
| 章节报告 | 记忆档案 | 查看本章新归档的证据 | 报告页退为底层，档案展开并定位新增节点 |
| 章节报告 | 下一游戏场景 | 合上报告，进入下一段昨日 | 继续按钮确认后，由章节线索接管 |
| 任意UI页 | 设置 | 抽出附属功能页 | 设置纸页从Icon来源展开 |

## 7.3 主菜单进入游戏

1. 记忆唤醒按钮完成有效Release。
2. 主按钮中的图像、暖光或纸面纹理成为画面焦点。
3. 其他按钮退回相册层，不逐个飞出。
4. 相册或档案边界从界面容器转化为场景入口。
5. 游戏场景建立后再开放场景触控。

## 7.4 主菜单进入记忆档案

1. 档案入口按钮完成普通确认。
2. 主菜单相册保持空间位置，退为桌面底层。
3. 档案Panel从明确装订边或档案盒方向展开。
4. 左分类栏与中央关系图建立。
5. 恢复上次浏览状态后开放交互。

## 7.5 游戏场景进入章节报告

1. 章节完成数据先提交。
2. 场景中的关键照片、日期或记忆线索成为报告来源。
3. 报告纸页铺开或落定。
4. 清晰度结果、恢复列表、未知记忆按阅读层级显露。
5. 页面Stable后允许列表浏览与按钮操作。

## 7.6 返回

- 返回使用进入路径的反向语义。
- 关闭右详情抽屉不触发整页转场。
- 关闭照片Focus先回到照片原位。
- 未完成重构按Interaction Bible处理继续或放弃，不直接播放离页转场。
- 返回后恢复浏览态，不重播页面首次叙事级进入。

## 7.7 转场打断

| 转场阶段 | 是否允许打断 | 处理 |
|---|---|---|
| Action尚未触发 | 允许 | 回到Idle或Selected |
| Transition Lock已建立 | 默认不接受重复触摸 | 等待目标接管或失败恢复 |
| Panel进入但未Stable | 不接受内部操作 | 完成进入或按系统中断规则恢复 |
| 目标加载失败 | 必须可恢复 | 逆向回来源页，恢复交互状态 |
| 应用切后台 | 系统级打断 | 保存已提交数据；未提交触摸不生效 |

# 08 Touch Feedback

## 8.1 反馈通道

| 通道 | 职责 |
|---|---|
| 视觉 | 确认触摸对象、状态变化与结果 |
| 声音 | 表达纸张、照片、档案、印章与记忆回应 |
| 触感 | 确认接触、合法放置、重要恢复和错误边界 |

反馈必须以视觉为主，声音与触感作为增强。静音或关闭振动时，核心操作仍应完全可理解。

## 8.2 Tap

| 通道 | 反馈规范 |
|---|---|
| 视觉 | 当前对象压入或聚焦；有效Release后完成一次确认 |
| 声音占位 | 轻纸触、题签、照片接触或图标对应旧物音 |
| 触感占位 | 轻触确认 |
| 取消 | 移出有效区则视觉逆向恢复，不播放确认反馈 |

## 8.3 Hold

| 通道 | 反馈规范 |
|---|---|
| 视觉 | 局部显影、清晰度保持或关注进度占位 |
| 声音占位 | 低强度持续记忆声，不循环制造紧张 |
| 触感占位 | 开始Hold时一次提示；达成时一次确认 |
| 取消 | 手指移出或系统中断后显影回落，不写入完成状态 |

Hold过程中显影达到可读程度后保持，不无限变亮或扩大。

## 8.4 Drag

| 通道 | 反馈规范 |
|---|---|
| 视觉 | 对象跟随触点；阴影表明被拿起；合法目标显示吻合反馈 |
| 声音占位 | 纸面摩擦、照片移动或碎片接近的轻提示 |
| 触感占位 | 合法目标进入、有效Drop时提供区分反馈 |
| 无效Drop | 对象回到上一个有效位置，不爆炸、不强烈抖动 |

## 8.5 Swipe

| 通道 | 反馈规范 |
|---|---|
| 视觉 | 内容随手指移动；纸页或列表保留重量与边界 |
| 声音占位 | 轻微翻阅或纸面滑动声，可按内容密度降低 |
| 触感占位 | 普通滚动不持续震动；到达明确边界时可有弱提示 |
| 边界 | 停止在合法范围，不拉出网页式弹性空白 |

## 8.6 Pinch

仅作为Memory Archive中央关系图的可选辅助。

| 通道 | 反馈规范 |
|---|---|
| 视觉 | 关系图整体比例变化，节点与连接同步 |
| 声音占位 | 默认无 |
| 触感占位 | 默认无；达到缩放边界可有弱提示 |
| 限制 | 不改变节点状态、不打开详情、不触发恢复 |

## 8.7 错误与无效操作

- 不使用强烈红闪、全屏震动或尖锐错误音。
- 无效Release以撤销Pressed为主要反馈。
- 错误放置使用轻微拒绝与返回原位。
- Disabled对象不播放可点击反馈。
- 重复点击被Action Lock拦截时，不重复播放完整确认。

# 09 Loading / Waiting Motion

## 9.1 世界观原则

加载与等待是“正在翻找、整理或恢复一段记忆”，不是系统计算过程。

禁止使用：

- 标准Loading圆圈。
- 百分比飞速跳动但没有叙事意义。
- 科技扫描条。
- 蓝色进度环。
- 无限旋转图标。

## 9.2 等待类型

| 等待类型 | 叙事隐喻 | 动态表现 |
|---|---|---|
| 启动与存档读取 | 打开旧档案盒并确认记录 | 档案标签、日期或纸页逐渐可读 |
| 章节资源准备 | 翻到下一页记忆 | 纸页边缘、章节题签或照片来源建立 |
| 记忆恢复处理 | 影像正在显影 | 照片由雾化走向局部清晰；不提前表现Completed |
| 档案数据等待 | 正在寻找对应记录 | 索引签与档案页保持轻微整理感 |
| 外部结果等待 | 记录尚未返回 | 保持当前页面上下文，使用可取消或说明状态 |

## 9.3 Loading状态

| 状态 | 动态要求 |
|---|---|
| Waiting Start | 明确当前操作已被接受，来源对象进入锁定反馈 |
| Waiting Active | 使用低强度、可持续的世界观运动；不遮挡必要说明 |
| Waiting Success | 收束当前等待动效，再交给目标状态 |
| Waiting Failure | 停止等待运动，恢复来源页，并提供克制的失败说明 |
| Waiting Cancel | 沿原路径回到操作前状态，不播放成功确认 |

## 9.4 长等待

- 保留清晰的当前任务说明。
- 若允许取消，取消入口必须稳定可见。
- 不让照片无限反复显影。
- 可使用不同旧纸细节轮换，但不制造虚假进度。
- 应用切后台时停止非必要Ambient Motion。

# 10 Motion Timing Guidelines

本章只规定相对节奏等级，不给出具体时间数值。

## 10.1 Timing Level

| 等级 | 名称 | 感受 | 适用内容 |
|---|---|---|---|
| T1 | Immediate | 手指与物件立即建立联系 | Touch Down、Drag跟随、滚动跟随 |
| T2 | Quick | 清晰、克制的操作确认 | 普通按钮Release、Tab选择、Icon关闭 |
| T3 | Deliberate | 有重量的页面或物件变化 | Panel展开、照片聚焦、详情抽屉 |
| T4 | Reflective | 允许玩家感受记忆正在恢复 | 照片修复、节点Recovered、章节归档 |
| T5 | Narrative | 叙事阈值与场景交接 | 开始回忆、进入过去、重大记忆恢复 |

## 10.2 节奏选择

| 情况 | 推荐等级 |
|---|---|
| 反馈必须跟手 | T1 |
| 高频重复操作 | T1–T2 |
| 页面结构改变 | T3 |
| 结果需要被看见 | T4 |
| 剧情入口或情绪高潮 | T5 |

## 10.3 节奏纪律

- T1反馈不能等待其他装饰动效。
- 高频操作不得使用T4或T5。
- T4、T5进行时减少并行动作。
- 同一操作链中，触控确认先于叙事级转场。
- 慢速不等于拖沓；每个阶段必须有明确的信息变化。

## 10.4 保持与停顿

- 关键恢复完成后允许一个稳定阅读阶段。
- 停顿用于让玩家辨认结果，不用于人为阻止操作。
- 普通按钮不增加戏剧性停顿。
- 报告页在Stable后才开放下一步操作。

# 11 Motion Token

## 11.1 Token结构

每个动态对象应引用以下Motion Token字段。

| Token字段 | 定义 |
|---|---|
| Motion ID | 全局唯一动态标识 |
| Motion Level | Narrative、Page、Component、Ambient |
| Motion Type | Press、Release、Reveal、Restore、Focus、Open、Close、Turn、Slide、Settle、Wait |
| Motion Priority | Critical、Primary、Secondary、Ambient |
| Source State | 动作开始前的Interaction状态 |
| Target State | 动作结束后的Interaction状态 |
| Timing Level | T1–T5相对节奏等级 |
| Direction | Z-In、Z-Out、Left、Right、Up、Down、Center-In、Local-Reveal |
| Anchor | 固定边、装订边、触点、照片中心、档案索引或场景来源 |
| Visual Channel | 纸张、阴影、边缘、图像、墨迹、连接、环境光 |
| Audio Slot | 声音反馈占位名称 |
| Haptic Slot | 触感反馈占位名称 |
| Interrupt Rule | 可逆、可取消、不可重复、等待提交或系统中断恢复 |
| Completion Gate | 何时允许Target State与数据提交 |
| Reduced Motion | 弱化动态时保留的必要状态变化 |

## 11.2 Motion Level Token

| Token | 含义 | 示例 |
|---|---|---|
| M1 Narrative | 关键叙事入口与记忆恢复 | 开始回忆、Recovered完成 |
| M2 Page | 页面结构与档案层级 | 打开档案、展开报告 |
| M3 Component | 单一控件状态变化 | Button Press、Tab Selected |
| M4 Ambient | 非必要环境运动 | 暖光、微尘、纸面环境呼吸 |

## 11.3 Motion Type Token

| Token | 用途 |
|---|---|
| Press | 纸张或物件压入 |
| Release | 从按下状态释放并确认 |
| Reveal | 内容从隐藏、模糊或褪色变得可辨认 |
| Restore | 破损内容重新完整 |
| Focus | 照片或节点成为当前视觉焦点 |
| Open | Panel、相册或抽屉展开 |
| Close | 沿来源路径合拢或收回 |
| Turn | 翻页或切换档案页 |
| Slide | 侧边档案抽屉与题签移动 |
| Settle | 归档、印章、连接或物件落定 |
| Wait | 加载与等待的世界观反馈 |

## 11.4 Motion Priority Token

| Priority | 规则 |
|---|---|
| Critical | 必须完成才能保证数据与页面一致；不可被普通触摸覆盖 |
| Primary | 当前页面唯一主要运动；可压制Secondary |
| Secondary | 从属反馈；不得遮挡Primary信息 |
| Ambient | 随时可停止；不影响理解与操作 |

## 11.5 Interrupt Rule Token

| Rule | 定义 |
|---|---|
| REVERSIBLE | 手指取消时沿原路径回到Source State |
| CANCELLABLE | 用户可明确取消，保留已提交数据 |
| LOCKED_AFTER_TRIGGER | Action Trigger后拒绝重复触发 |
| COMPLETE_BEFORE_EXIT | 必须完成状态收束后才能离页 |
| SYSTEM_RECOVERABLE | 系统中断后恢复到最近稳定状态 |
| AMBIENT_DROPPABLE | 可随时停止且不影响状态 |

## 11.6 Motion Record模板

| 字段 | 填写要求 |
|---|---|
| Identity | Motion ID、Element ID、Page ID |
| State Path | Source State → Target State |
| Meaning | Discover、Awaken、Restore、Confirm或Recede |
| Hierarchy | Motion Level与Priority |
| Material | 受影响的纸张、照片、阴影、边缘、墨迹或连接 |
| Rhythm | Timing Level |
| Feedback | Audio Slot与Haptic Slot |
| Interrupt | Interrupt Rule与失败恢复目标 |
| Gate | Completion Gate与数据提交关系 |
| Reduced Motion | 保留哪些必要反馈，删除哪些装饰运动 |

# 12 Reduced Motion & Feedback Accessibility

## 12.1 原则

弱化动态模式不改变状态、不改变页面流程，也不删除必要确认。它只减少位移、视差、缩放、环境循环与复杂聚合过程。

## 12.2 弱化规则

| 原动态 | Reduced Motion处理 |
|---|---|
| 大范围Panel翻开 | 改为较小位移的层级展开与清晰度建立 |
| 照片大幅聚焦 | 保留轻微抬升与清晰度变化 |
| 碎片聚合 | 保留位置变化与边缘闭合，减少旋转和路径弧度 |
| 全屏暖光进入过去 | 保留局部来源与场景交接，降低大范围亮度变化 |
| Ambient Motion | 停止或显著降低 |
| 按钮Press | 必须保留压入、阴影与有效Release确认 |

## 12.3 声音与触感独立性

- 关闭声音后，视觉必须仍能表达所有状态。
- 关闭触感后，视觉与声音必须仍能表达有效和无效操作。
- 不使用连续强触感表现记忆恢复。
- 错误反馈不得依赖单一声音或单一颜色。

# 13 Motion QA Checklist

## 13.1 世界观检查

| 检查项 | 通过标准 |
|---|---|
| 旧物感 | 纸、照片、档案具有重量、固定边和来源方向 |
| 记忆感 | 关键运动体现发现、唤醒、恢复或确认 |
| 克制 | 没有无意义弹跳、爆炸、霓虹或持续发光 |
| 连贯 | 页面进入与退出方向相互对应 |

## 13.2 状态检查

| 检查项 | 通过标准 |
|---|---|
| Touch Down | 立即确认接触对象 |
| Invalid Release | 可逆恢复，不触发Action |
| Selected | 回到正确业务状态，而非一律Idle |
| Completed | 归档表现稳定，不重复播放恢复 |
| Transition Lock | 不接受重复Action |
| 系统中断 | 未提交操作不写入，已提交结果不丢失 |

## 13.3 层级检查

| 检查项 | 通过标准 |
|---|---|
| 主运动唯一 | 同屏没有两个竞争的Level 1运动 |
| 从属运动克制 | 图标、胶带、回形针不独立表演 |
| 阅读稳定 | 正文在阅读阶段不漂移、不抖动 |
| 触控可用 | 动态不改变Visual Bible既定Hitbox |

## 13.4 页面检查

| 页面 | 必查内容 |
|---|---|
| 主菜单 | 开始回忆Motion Flow、普通按钮与记忆唤醒按钮差异 |
| 记忆档案 | Panel展开、Node Selected、详情抽屉、关系图状态 |
| 照片重构 | Drag、合法Drop、失败返回、Recovered稳定 |
| 章节报告 | 场景到报告、阅读稳定、继续下一章节 |
| 设置 | Level 2进入与关闭，不使用叙事级恢复效果 |

## 13.5 边界检查

| 禁止项 | 验收 |
|---|---|
| 修改1280×720 LP与Safe Area | 不得出现 |
| 修改Button、Hitbox、字体或材质 | 不得出现 |
| 指定HTML/CSS/Unity实现 | 不得出现 |
| 写程序代码 | 不得出现 |
| 提供具体毫秒时长 | 不得出现 |
| 用普通Fade替代全部页面转场 | 不得出现 |

# 14 最终动态准则

任何动效进入制作前，都必须回答：

| 问题 | 必须明确的答案 |
|---|---|
| 玩家触碰了什么？ | 一张纸、照片、题签、节点、档案或场景旧物 |
| 这次运动表达什么？ | 发现、唤醒、恢复、确认或褪去 |
| 哪个对象是动态焦点？ | 同一时刻唯一主对象 |
| 动作结束后进入什么状态？ | Interaction Bible定义的明确Target State |
| 何时写入数据？ | Completion Gate满足之后 |
| 如果取消或中断会怎样？ | 回到最近稳定、可解释的状态 |
| 弱化动态后还剩什么？ | 必要的触控、状态与完成反馈 |

> 《昨日重现》的动态不是为了证明界面会动。  
> 动态存在，是为了让玩家相信：自己的手指真的触碰到了一件旧物，而那件旧物仍然记得过去。
